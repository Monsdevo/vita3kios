==============================================================================
1. DEĞİŞMEZ ÜRÜN TANIMI
==============================================================================

Ürün adı:
  - Kullanıcıya görünen ad: vita3kios
  - Okunuş/marka fikri: "vita-3-kios"
  - Kod içi Swift modül/target adı: Vita3KiOS
  - Bundle identifier: imzalama aşamasında belirlenecek; kaynakta sabit kişisel
    takım kimliği tutulmayacak.

Ana hedef:
  - Açık kaynak Vita3K emülatör çekirdeğini arm64 iPhone/iPad üzerinde çalışan,
    Apple-native bir uygulama içinde sunmak.
  - Uygulamanın kendi sade, açıklayıcı ve native arayüzü olacak.
  - Kullanıcı yasal olarak edindiği/dump ettiği içeriği Files üzerinden içe
    aktarabilecek, kütüphanede görebilecek ve boot edebilecek.
  - Oyun sırasında görüntü, ses, dokunmatik Vita yüzeyleri, fiziksel kontrolcü,
    cihaz hareketi ve yaşam döngüsü iOS'a uygun şekilde yönetilecek.
  - İki ayrı çalıştırma modu olacak:
    1) Direct Game Mode: seçilen oyunu Vita system shell'i açmadan doğrudan boot.
    2) System Software Mode: kullanıcının kurduğu resmi PS Vita firmware'indeki
       gerçek sistem yazılımını/LiveArea shell'ini çalıştır; oyunlar bu ortamdan
       da seçilip başlatılabilsin.
  - "Firmware kuruldu" tek başına System Software Mode tamamlandı demek değildir.
    Başarı, gerçek firmware UI'ının etkileşimli boot etmesiyle ölçülecek.
  - Version 1.0, MSYS kilometre taşı tamamlanmadan yayınlanmış sayılmayacak.
    Daha erken teknik alpha'lar Direct Game Mode ile yayımlanırsa System Software
    desteğinin eksik olduğu görünür biçimde yazılacak.
  - Ayarlar basit bir aç/kapat ekranı olmayacak. Global, Direct Game, System
    Software ve title-specific profiller; Basic/Advanced görünümü; arama,
    açıklama, varsayılana dönme ve güvenli migration içerecek.
  - Direct Game ve System Software oturumlarının ikisinde de sağ üstte küçük,
    okunabilir bir performans HUD'ı olacak. HUD kapatılabilir ve özelleştirilebilir
    olacak; varsayılanı Compact görünüm olacak.

İlk sürümün ana dağıtım hedefi:
  - Gerçek cihazda geliştirici imzası veya sideload edilmiş IPA.
  - Performans sürümü için JIT etkinleştirilmiş çalışma yolu.
  - App Store sürümü ayrı bir karar kapısıdır; ilk çalışan portun ön koşulu
    değildir ve şimdiden vaat edilmez.

Kapsam dışı / yasak başlangıç kapsamı:
  - Sony firmware'i, oyunları, lisans anahtarlarını veya şifre çözme verilerini
    uygulamayla dağıtmak.
  - Korsan içerik mağazası, oyun indirme kataloğu veya benzeri kaynak eklemek.
  - Masaüstü Qt arayüzünü iOS'a taşımak veya iOS ekranına gömmek.
  - İlk günden tüm Vita3K uyumluluk listesini desteklediğini iddia etmek.
  - Simulator'ı gerçek emülasyon performans hedefi saymak.
  - Ölçülmüş bir engel olmadan Vulkan renderer'ı baştan Metal ile yazmak.

Başlangıç teknik kararları:
  - Arayüz: SwiftUI; gerektiğinde küçük UIKit/MetalKit köprüleri.
  - Çekirdek: upstream Vita3K C++ kodu; CMake ile derleme.
  - Swift/C++ sınırı: kararlı bir C ABI; Swift doğrudan C++ nesnesi görmeyecek.
  - CPU: önce Vita3K'nın Dynarmic A32->A64 yolu.
  - GPU: önce Vita3K Vulkan renderer + MoltenVK + CAMetalLayer.
  - Native servisler: GameController, CoreMotion, AVFoundation/AudioToolbox,
    os/log, UIKit scene lifecycle ve Files document picker.
  - Minimum iOS: ilk teknik varsayım iOS 17.4; Faz 2A'da gerçek cihaz ve JIT
    sonuçlarına göre yükseltilebilir. Düşürme ancak test kanıtıyla yapılır.
  - Desteklenen işlemci: yalnızca arm64 gerçek cihaz. Simulator UI ve parser
    testleri için kullanılabilir; oyun çalıştırma desteği garanti edilmez.

Lisans ilkesi:
  - Upstream Vita3K GPLv2 kapsamındadır. Birlikte dağıtılan uygulama ve çekirdek
    için GPL yükümlülükleri korunacak; tam karşılık gelen kaynak, lisans ve
    değişiklik bilgisi her binary sürümle erişilebilir olacak.
  - Tüm üçüncü taraf bağımlılıkların lisansı Faz 1'de envanterlenecek.
  - Bu bölüm hukuki görüş değildir; halka açık dağıtımdan önce lisans kontrolü
    ayrıca tamamlanacaktır.

Katmanlar ve sorumluluklar:

  A. Native App katmanı
     - SwiftUI kütüphane, ayarlar, import, hata ve onboarding ekranları.
     - SwiftData/Core Data seçimi yapılmadan önce veri modeli ölçülecek; oyun
       dosyalarının kendisi veritabanına konmayacak.
     - Uygulama yaşam döngüsü, erişilebilirlik ve yerelleştirme.

  B. Session Coordinator
     - Tek bir emülasyon oturumunun durum makinesi:
       idle -> preparing -> waitingForJIT -> booting -> running <-> paused
       -> stopping -> idle; hata durumundan kontrollü temizleme.
     - UI thread üzerinde bloklama yapmama.
     - Aynı anda ikinci oyun açılmasını engelleme.
     - Oturum türünü ayrı taşıma: directGame(titleID) veya systemSoftware.
     - System Software içinden oyun açıldığında oturumun shell->title->shell
       geçişini ve ilgili save/config sahipliğini koruma.

  C. Vita3KBridge C ABI
     - create/destroy, initialize, install, enumerate, boot, pause, resume, stop.
     - Frame/surface, input, audio, log, progress ve hata callback'leri.
     - C++ exception'ları ABI dışına kaçırmama; tipli hata kodu + açıklama.
     - ABI sürümü ve capability sorgusu.
     - Ayrı boot entry point'leri: boot_title ve boot_system_software.
     - Ayar şeması/capability/etkin değer sorguları ve tipli setting mutation.
     - HUD snapshot callback'i: frame timing, emulation speed, CPU/GPU/JIT,
       memory, thermal ve audio sayaçlarından desteklenenler.

  D. iOS Platform katmanı
     - Sandbox path çözümleme, güvenli atomik yazım, geçici alan yönetimi.
     - CAMetalLayer/MoltenVK yüzeyi.
     - Executable memory/JIT adaptörü.
     - GameController/CoreMotion/touch girişleri.
     - Audio session ve düşük gecikmeli ses çıkışı.
     - Foreground/background, interruption, thermal/memory pressure olayları.

  E. Upstream Vita3K Core
     - CPU, kernel, HLE modülleri, GXM/shader çevirisi, Vulkan renderer,
       paket/firmware işleme, sanal dosya sistemi.
     - Qt GUI ve masaüstü main() iOS binary'sine bağlanmayacak.
     - Upstream firmware installer'ın LLE modülü kurması ile gerçek firmware
       shell boot yolu ayrı tutulacak; eksik boot-chain/HLE/LLE işi ayrıca izlenecek.

Bağımlılık stratejisi:
  - Upstream kaynak ve alt modülleri yeniden kopyalanmayacak; Git submodule ile
    kesin commit pinlenecek.
  - iOS yamaları önce PlatformIOS/Bridge içinde tutulacak.
  - Upstream dosyası değişmek zorundaysa küçük, konulu commit yapılacak.
  - Qt, Discord SDK ve masaüstüne özel bileşenler iOS build graph'ından çıkarılacak.
  - Her iOS bağımlılığı için: arm64 slice, bitcode beklentisi yokluğu, exception/
    RTTI ihtiyacı, lisans, dynamic/static bağlantı ve private API kontrolü yapılacak.

R2 — Vita3K core ile Qt/desktop kodunun sıkı bağlı olması
  Etki: iOS compile/link karmaşası.
  Tepki: interface.cpp ve Android frontend desenlerinden UI'sız core API çıkarılır;
  Qt iOS app'e sokulmaz.

R3 — Vulkan özelliklerinin MoltenVK karşılığı
  Etki: shader doğruluk hatası, eksik extension veya düşük performans.
  Tepki: Upstream Apple renderer yolu başlangıç alınır; feature report + GPU capture.
  Native Metal yalnızca somut, belgeli blokerde ayrı planla başlar.

R4 — iOS sandbox/lifecycle
  Etki: provider URL kaybı, background crash, bozuk import/save.
  Tepki: staging+atomik taşıma, göreli kalıcı yollar, pause/stop state machine ve
  interruption testleri.

R5 — Bellek ve termal limit
  Etki: jetsam, throttling, ses/frame düşmesi.
  Tepki: gerçek cihaz Instruments ölçümü, cache budget, 1x güvenli varsayılan,
  thermal/memory olaylarına kontrollü tepki.

R6 — Upstream'in hızlı değişmesi
  Etki: port yamalarının çürümesi.
  Tepki: submodule pin, küçük commitler, otomatik regression ve planlı sync.

R7 — Lisans/dağıtım
  Etki: binary yayınlayamama veya kaynak yükümlülüğü ihlali.
  Tepki: GPL kaynak eşleme, dependency manifest, üçüncü taraf notices ve Store'u
  ayrı karar kapısı yapmak.

R8 — İçerik ve marka hukuku
  Etki: proje/dağıtım riski.
  Tepki: firmware/oyun/key yok; kullanıcı dump'ı; Sony ile bağlantısızlık metni;
  resmi olmayan logoları/assetleri uygulamaya koymama.

6. TEST POLİTİKASI
==============================================================================

Her fazda:
  - Debug ve Release derlemesi mümkün olan yerde test edilir.
  - Yeni uyarı, crash, hang ve veri kaybı regresyon sayılır.
  - Simulator sonucu gerçek cihaz/JIT/GPU kanıtı yerine geçmez.

  - Test logunda app commit + upstream commit + cihaz/iOS + ayarlar bulunur.

Minimum sürekli test grupları:
  A. Parser/import fixtures (oyun içermeyen sentetik veriler)
  B. Bridge lifecycle ve concurrency
  C. Dynarmic instruction/JIT smoke
  D. MoltenVK surface/frame smoke
  E. Açık kaynak homebrew boot/input/audio
  F. Kullanıcıya ait yasal retail dump manuel uyumluluk matrisi
  G. Tekrarlı boot/stop, background/foreground, memory/thermal stress
